# 手動確認手順: サーバーエラー系

## 対象観点

- `VP-COMMON-API-006`: サーバーエラー時に500を返すこと
- `VP-COMMON-ERROR-001`: サーバーエラー・通信エラーを再現する方法と期待結果をテスト実施前に記録すること

## Playwright自動確認

`viewpoint-table.spec.ts` では、次の観点を自動確認する。

- `VP-COMMON-UI-001`: `page.route()` で `/api/todos` を500応答に差し替え、画面メッセージを確認する。
- `VP-COMMON-UI-002`: `page.route()` で `/api/todos` を通信失敗にし、画面メッセージを確認する。
- `VP-COMMON-API-006`: 不正JSONを送信してExpressの共通エラーハンドラ経由で500応答を確認する。

## 手動確認が必要な場合

`TC-COMMON-API-006-01` が環境差により500以外を返す場合は、次の手順で手動確認する。

1. `npm run dev` でReactとExpressを起動する。
2. 一時的に `server/index.js` の `GET /api/todos` または `POST /api/todos` が `throw new Error('manual server error')` を実行するようにする。
3. ブラウザでログインする。
4. メモ一覧を表示、またはメモ登録を実行する。
5. APIレスポンスのHTTPステータスが `500` であることをブラウザ開発者ツールまたは `curl` で確認する。
6. 画面に `処理中にエラーが発生しました。時間をおいて再度お試しください。` または現行実装の共通エラーメッセージが表示されることを確認する。
7. 手順2の一時変更を必ず戻す。

## 合否基準

- APIが `500` を返すこと。
- 画面に利用者向けのエラーメッセージが表示されること。
- パスワード、認証トークン、スタックトレースなどの機密情報が画面またはAPIレスポンスに表示されないこと。
