# メモ帳アプリQAテスト共通事項

## 1. 目的

本書は、React、Express、SQLiteで構成されたメモ帳アプリについて、機能テスト、画面テスト、APIテスト、データ整合性テストを実施するための共通事項を定める。

## 2. 対象システム

- Reactフロントエンド
- Express APIサーバー
- SQLiteデータベース
- メモ管理機能
- ユーザー管理・認証機能
- 権限管理機能
- タグ、お気に入り、下書き機能
- ファイル添付・画像アップロード機能

## 3. テスト環境

- Node.jsおよびnpmが利用できること
- 依存パッケージをインストール済みであること
- React開発サーバー: `http://localhost:5173`
- Express APIサーバー: `http://localhost:3001`
- SQLite DB: `data/memo.db`
- 対象ブラウザを明記すること
- テスト実施前にDBとアップロードディレクトリの状態を確認すること

## 4. テスト対象機能

### 4.1 認証

- ユーザーIDとパスワードによるログイン
- ログイン成功後のメモ一覧への遷移
- ログイン失敗時のエラー表示
- 未ログイン状態での保護画面・APIへのアクセス制御
- ログアウト
- 無効化ユーザーのログイン拒否

### 4.2 メモ管理

- メモ一覧表示
- メモ新規作成
- メモ詳細表示
- メモ編集
- メモ削除確認と削除
- 更新日時の新しい順での一覧表示
- 削除済みメモの非表示

### 4.3 検索・表示制御

- タイトル・本文の部分一致検索
- 英字の大文字・小文字を区別しない検索
- 空欄検索による全件表示
- 検索結果0件時のメッセージ表示
- ページング
- 作成日時、更新日時、タイトルによる並び替え
- 昇順・降順の切り替え
- お気に入りによる絞り込み
- タグによる絞り込み

### 4.4 入力チェック

- タイトルの必須、空白のみ、100文字上限
- 本文の必須、空白・改行のみ、2,000文字上限
- ユーザーIDの形式・文字数・一意性
- パスワードの必須・文字数
- タグ名の文字数・重複
- 添付ファイルの拡張子・サイズ・件数
- 画像の形式・サイズ・枚数
- 入力エラー時の画面遷移抑止
- 複数エラーの同時表示

### 4.5 安全性

- 日本語、英数字、記号、絵文字、改行の入力
- HTMLタグやJavaScript相当文字列の文字列表示
- XSSが発生しないこと
- パスワードが画面やレスポンスに平文表示されないこと
- 権限外メモを参照・編集・削除できないこと
- 権限外ファイルをダウンロードできないこと

### 4.6 ユーザー・権限管理

- 管理者によるユーザー一覧表示
- ユーザー作成
- ユーザー編集
- ユーザー無効化
- 管理者は全画面・全ユーザーのメモを操作できること
- 一般ユーザーは自分のメモのみ操作できること
- 一般ユーザーがユーザー管理画面へアクセスできないこと

### 4.7 タグ・お気に入り

- メモへのタグ付与
- 同一メモ内のタグ重複防止
- タグ一覧表示
- タグ絞り込み検索
- お気に入り登録・解除
- ユーザーごとのお気に入り状態保持

### 4.8 ファイル・画像

- 添付ファイルの追加・削除
- 添付ファイルのダウンロード
- 画像の追加・削除
- 画像プレビュー
- 添付ファイルの最大5件、1件10MB制限
- 画像の最大10枚、1枚5MB制限
- 許可拡張子・画像形式の検証

### 4.9 自動保存・競合制御

- 入力変更から3秒後の下書き保存
- 下書き保存成功メッセージ
- 下書きの復元
- 下書き保存失敗時も手動保存できること
- 編集開始後の他ユーザー更新の検知
- 競合発生時の入力内容保持

## 5. テストデータ

以下のデータを準備してテストする。

- 管理者ユーザー
- 一般ユーザー
- 無効化ユーザー
- 正常なタイトル・本文
- 空文字、半角スペース、全角スペース、改行のみの入力
- タイトル0、1、100、101文字
- 本文0、1、2,000、2,001文字
- 日本語、半角英数字、全角英数字、記号、絵文字
- `<script>alert(1)</script>` などのHTML・JavaScript文字列
- 重複タグ、大文字・小文字だけが異なるタグ
- 許可拡張子と不許可拡張子のファイル
- サイズ上限内外のファイル・画像
- 自分のメモ、他ユーザーのメモ、削除済みメモ
- 同時編集確認用の古い更新日時

## 6. 共通確認事項

各テストケースで、次の項目を確認する。

- 画面が正しく表示されること
- 入力値が正しく保持されること
- 成功メッセージが仕様どおりであること
- エラーメッセージが仕様どおりであること
- 画面遷移が仕様どおりであること
- APIのHTTPステータスが適切であること
- APIレスポンスの項目と値が正しいこと
- DBの登録・更新・削除結果が正しいこと
- 日時が `YYYY/MM/DD HH:mm:ss` 形式で表示されること
- 登録・更新処理中に二重送信できないこと

## 7. API共通確認

- 認証トークンなしで保護APIへアクセスした場合の拒否
- 不正な認証トークンの拒否
- 権限不足時の拒否
- 必須パラメータ不足
- 不正なJSON・不正な型
- 不正なID・存在しないID
- 存在しないメモ、ユーザー、ファイルへのアクセス
- 不正なHTTPメソッド
- サーバーエラー時の共通メッセージ
- 通信エラー時の共通メッセージ

主なAPIは以下のとおり。

- `POST /api/login`
- `POST /api/logout`
- `GET /api/me`
- `GET /api/todos`
- `POST /api/todos`
- `GET /api/todos/:id`
- `PUT /api/todos/:id`
- `DELETE /api/todos/:id`
- `GET /api/users`
- `POST /api/users`
- `PUT /api/users/:id`
- `PATCH /api/users/:id/disable`
- `GET /api/tags`
- `POST /api/todos/:id/favorite`
- `DELETE /api/todos/:id/favorite`
- `GET /api/drafts/new`
- `GET /api/drafts/memos/:memoId`
- `POST /api/drafts`
- `DELETE /api/drafts/:type/:memoId?`
- `DELETE /api/files/:fileId`
- `GET /api/files/:fileId/download`

## 8. データ整合性

- メモIDは登録後に変更されないこと
- 作成日時は編集時に変更されないこと
- 更新日時は編集時に更新されること
- 削除済みメモが一覧・検索結果に表示されないこと
- ユーザーIDが一意であること
- 無効化ユーザーがログインできないこと
- タグが同一メモ内で重複しないこと
- お気に入り状態がユーザーごとに保持されること
- 添付ファイル・画像が正しいメモに紐付くこと
- 削除済みファイルをダウンロードできないこと

## 9. 非機能確認

- 長文入力時にレイアウトが崩れないこと
- 多数のメモでページングが機能すること
- 登録・更新・削除中にボタンが無効化されること
- 不正ファイルを保存できないこと
- パスワードを平文保存しないこと
- ファイルパスを操作して任意ファイルを取得できないこと
- XSS、権限逸脱、認証回避が発生しないこと
- 主要ブラウザで基本操作ができること

## 10. エラー処理

サーバーエラー時は次のメッセージを表示する。

`処理中にエラーが発生しました。時間をおいて再度お試しください。`

通信エラー時は次のメッセージを表示する。

`通信に失敗しました。ネットワーク接続を確認してください。`

登録・更新に失敗した場合は、入力内容を保持すること。

## 11. テスト結果の記録項目

- テストケースID
- 機能名
- 前提条件
- 使用ユーザー
- 使用データ
- 操作手順
- 期待結果
- 実際の結果
- APIレスポンス
- DB確認結果
- 合否
- 不具合番号
- 備考

## 12. 実施手順

1. `npm install` を実行する。
2. `npm run dev` でReactとExpressを起動する。
3. テスト用ユーザーでログインする。
4. 機能別に正常系、異常系、境界値を確認する。
5. 必要に応じてAPIレスポンスとSQLiteの内容を確認する。
6. テスト結果と不具合を記録する。
7. テスト終了後、作成したテストデータを整理する。

### 12.1 スクリーンショット比較手順

`VP-MEMO-LIST-006` は、長いタイトルや本文を持つメモでも一覧表示が崩れないことをPlaywrightのスクリーンショット比較で確認する。

1. 長いタイトル、長い本文、英数字の連続文字列、改行を含む本文を持つメモをテストデータとして登録する。
2. メモ一覧画面を開き、対象メモが表示される状態にする。
3. 表示件数、検索条件、並び順を固定し、スクリーンショットの差分が不安定にならない状態にする。
4. Playwrightで対象領域、またはページ全体のスクリーンショットを取得し、基準画像と比較する。
5. 初回実行時は `npx playwright test --update-snapshots` で基準画像を作成する。
6. 2回目以降は `npx playwright test` を実行し、差分が許容範囲内であることを確認する。
7. 差分が発生した場合は、Playwrightレポートの `actual`、`expected`、`diff` 画像を確認し、意図したUI変更か表示崩れかを判定する。

判定基準は次のとおりとする。

- タイトルや本文がカード、一覧行、ボタン、ページネーションなど他のUI要素に重ならないこと。
- 横スクロールが発生しないこと。ただし、仕様として許可された領域内スクロールは除く。
- 詳細、編集、削除などの操作ボタンが表示され、クリック可能な位置にあること。
- 一覧の余白、折り返し、省略表示が基準画像と大きく異ならないこと。
- 動的な日時やテストデータ名により差分が出る場合は、比較対象領域を限定するか、固定データを使用すること。

Playwright実装例:

```ts
test('TC-MEMO-LIST-006-01 / VP-MEMO-LIST-006 長文メモでも一覧表示が崩れない', async ({ page, request }) => {
  const token = await loginByApi(request);
  const title = `TC-MEMO-LIST-006-${'LongTitle'.repeat(10)}`;
  await createMemo(request, token, {
    title,
    body: `${'長い本文です。'.repeat(80)}\n${'abcdefghijklmnopqrstuvwxyz'.repeat(20)}`,
  });

  await openLoggedInPage(page, request);
  await page.getByLabel('検索').fill('TC-MEMO-LIST-006');
  await expect(page.getByText(title)).toBeVisible();
  await expect(page.getByRole('button', { name: '詳細' }).first()).toBeVisible();
  await expect(page.getByRole('button', { name: '編集' }).first()).toBeVisible();
  await expect(page.getByRole('button', { name: '削除' }).first()).toBeVisible();

  await expect(page).toHaveScreenshot('VP-MEMO-LIST-006-long-memo-list.png', {
    fullPage: true,
    maxDiffPixelRatio: 0.05,
  });
});
```

## 13. 注意事項

- 本番環境のDBやアップロードファイルをテストに使用しないこと。
- パスワードや認証トークンをテスト結果へ記録しないこと。
- テスト用ファイルは許可された拡張子・サイズで準備すること。
- 論理削除されたデータは通常の一覧に表示されないことを前提とする。
- 自動保存の確認では、入力変更後3秒以上待機すること。
- 同時編集の確認では、保存前に別セッションから同じメモを更新すること。
- テスト終了後も再現に必要なマスターユーザーは削除しないこと。
